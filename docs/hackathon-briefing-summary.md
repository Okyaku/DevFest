# DevFest GDG Japan Hackathon 2026 説明会要約

文字起こし `transcription.txt` をもとにした要約。特に失格・審査対象外につながる条件を優先して整理した。

## 最優先：失格・審査対象外を避けるチェックリスト

- チームは **2〜4名**。全員が参加登録済みで、**11月4日までに Discord 参加**が必要。
- 対象者は、18歳以上で、日本国内に居住し、日本の大学・大学院・短大・高専・専門学校に在籍する学生。企業・団体で正社員／契約社員等として **通算1年以上**働いた経験がある人は対象外。アルバイト、インターン、業務委託は参加資格に影響しない。
- プロダクトは次の **5カテゴリーのいずれか**に属するものにする：**医療・福祉／観光／教育／エンターテインメント／クリエイティブ**。カテゴリー外のプロダクトは審査対象外。
- 開発開始アナウンス前（11月5日 10:00前）は、プロダクトのソースコード作成と CI/CD 構築をしない。環境整備、技術検証用 POC、UIデザイン検討は可。ただし、**POC のコードを本番リポジトリへコピー・流用すると違反となり、失格の可能性**がある。
- アプリ実行には、次の指定実行基盤のうち **1つ以上**を用いる必要がある。未使用のプロダクトは審査対象外となる可能性がある：**App Engine／Compute Engine／GKE／Cloud Run／Firebase App Hosting／Firebase Hosting**。
- Google 以外の LLM API を内部利用すること自体は禁止ではない。ただし、他社AI・他社製品を前面に出す、または他社AIツールが主技術のプロダクトは、事前審査で足切り・審査対象外となる可能性がある。主技術は Google 技術にする。
- APIキーや個人情報を、運営提供の提出用リポジトリへコミットしない。
- 著作物利用シートを提出する。GDG コミュニティガイドラインを遵守する。
- 提出用 Google Drive フォルダは **「リンクを知っている全員が閲覧可能」**にする。審査員が開けないと審査不能となり、失格の可能性がある。
- 現地会場でピッチ進出した場合、Regional Day に **最低1名の現地参加が必須**。全員参加不可なら運営へ申請の上、順位繰上げとなる。

## 開発・提出

### 開発期間とリポジトリ

- 開発期間は **11月5日 10:00〜11月10日 17:00**。締切後、提出用リポジトリは読み取り専用となり変更不可。
- 開発中は自分たちのリポジトリを使ってよい。運営提供の GitHub Organization 内のチーム用リポジトリには、最終成果物を push する。
- 運営提供リポジトリは無料プランのため、GitHub Actions 等が使えない見込み。開発期間中の GitHub Actions 利用申請はすべて却下される。
- 決勝進出チームのみ、予選後〜Demo Dayまで追加開発できる。

### 提出物（全5点）

1. 運営提供 GitHub リポジトリ（最終成果物）
2. プロダクト説明ドキュメント（運営テンプレート使用）
3. デモ動画（オンライン会場は、デモを含むプレゼン動画）
4. 著作物利用シート（運営テンプレート使用）
5. ピッチ用スライド（現地会場申込者のみ。当日ピッチ用）

- 会場別の Google Form に、GitHub URL と提出物を入れた Google Drive フォルダ URL を提出する。
- 提出資料には Google Cloud アーキテクチャ図も含まれる。公式アイコン等を利用し、Google Drive に入れる。
- デプロイURLを提出して審査員に実機を見せる場合は、Regional Day まで稼働させる。スクリーンショット等で代替できる場合は必須ではない。

## 審査

審査軸は次の4つ。

1. Google 技術の活用
2. プロダクトの完成度
3. 社会課題への解決力
4. ピッチ構成・説明

- 事前審査でピッチ進出を決めるため、ドキュメントとデモ動画の品質が重要。
- 参加チームが **20チーム超の会場のみ**事前足切りを行い、上位約20チームが Regional Day でピッチする。20チーム以下の会場は全チームがピッチ。
- オンライン会場は同期ピッチなし。書類審査のみで決勝3チームを選び、提出するプレゼン動画がピッチ評価そのものとなる。
- AIを「どの場面でどう使ったか／なぜ使ったか」、開発を通じた「得たこと・成長」を採点外項目として記載する。ここでは Google 以外のAIモデルへの言及も可。
- Demo Day は1チーム6分、デモファースト（何を作ったか・なぜ作ったかを説明してデモ）。Regional Day の点数は持ち越さず、決勝のみで再審査する。
- 決勝枠は計9チーム：東京3、大阪2、名古屋1、オンライン3。

## クラウドクレジットとコスト

- 1チーム **Google Cloud クレジット 20米ドル**。有効化にクレジットカード登録が必要だが、20ドル以内の利用分は請求されない。
- このクレジットは Google AI Studio には適用されない。LLM API利用は AI Studio 経由のキーではなく、Vertex AI（説明会では「エージェントプラットフォーム」経由と説明）を使うよう案内されている。
- 予算アラート（例：10/15/20ドル）、未使用リソースの停止、API利用制限を設定する。デプロイURLを維持するなら残高・期限も確認する。

## 個人枠

- 11月3日12:00締切後、同日14:00頃から運営が3〜4名のオンラインチームを編成し、専用テキスト／ボイスチャンネルを作成する。
- チーム名確定後、チーム名確定フォームに入力する。
- 再チームビルディング申請は **11月6日 10:00まで**、かつ **メンバーと連絡が取れない場合のみ**。スキル差・コミュニケーションを理由にはできない。
- 11月5日までの顔合わせを推奨。

## 連絡・次にやること

- 運営連絡はすべて Discord のアナウンスチャンネル。通知をオンにする。
- 質問は Discord のお問い合わせチャンネルで `@運営サポート` をメンションする。
- 早急に、全員のDiscord参加、GitHub招待の承認、配布予定のクレジット資料・ルール・提出テンプレートの確認を行う。
- 開発開始前に、カテゴリーと解決する課題を決める。ただしコードは書かない。
- 決勝の可能性に備え、**11月27日〜29日を空ける**。決勝進出者には移動・宿泊支援があるが、DevFest Tokyo向け宿泊支援には上限がある。宿泊は男性は相部屋、女性は人数事情により個別手配の予定。
